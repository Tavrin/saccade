Visual regression tests that score what a person would notice.

saccade compares baseline images with fresh captures using NVIDIA FLIP, a perceptual error metric. It boxes the regions where the error is, describes the change in plain English and exits 1 on a regression.

  • Scores how visible a change is, so a 1-bit dither change and a visible colour error do not count alike.
  • Given capture metadata, reports an error instead of a verdict when the two runs used different settings.
  • Built for agents: lean JSON results, hotspot crops, server-side snapshots and an MCP server.
Try it: Rust 1.88+
$ git clone https://github.com/Tavrin/saccade
$ cd saccade
$ cargo run --release -p saccade -- compare examples/baseline examples/capture --out report

Built for AI agents

An agent that cannot open the report still gets where and how much

Every command takes --json. Failures carry hotspots, a change class and a next_step. Images an agent needs to look at come as small crops or a rendered snapshot.

MCP server: saccade mcp

A Model Context Protocol server over stdio. Every path the agent passes must resolve under --root; a path that escapes it, through .. or a symlink, is refused with unsafe_path. Every tool declares an output schema.

Judge packs: saccade explain

Turns a report into one [baseline | capture | heatmap] strip per hotspot, plus explain.json and explain.md. With --blind, each strip is [A | B] in a random order with no heatmap, and the key is written outside the pack.

Snapshots without a browser: saccade snapshot

Renders any view state of a report entry to a PNG on the command line: layout, split, zoom, heatmap and hotspot boxes. Pages also keep their whole view in the URL hash and expose window.saccade for browser automation.

Model answers are proposals

saccade decision-request asks fixed questions with closed answer sets (accept, triage, cause, ask_human, mask_suggest) and a deterministic request hash. saccade decide records a model's answer as a proposal that a person confirms or overrides. approve reads final decisions only, so a proposal never moves a baseline. An optional confidence gate in saccade.toml can promote accept or reject answers above a probability you set, from sources you allow.

Decisions you can trust

What keeps a verdict from being wrong in silence

A verdict is only useful if it fails loudly when its inputs are wrong. These checks are part of the tool, not advice.

Mismatched captures are refused

Metadata sidecars record how each image was captured: renderer mode, resolution, driver. With --require-matching-meta, a difference that was not declared is an error, not a pass or a fail. Timing keys are paired and shown, never gated.

Deterministic failures never go to a model

A NaN or all-black capture, a config mismatch, an identity break and an error status are listed under skipped in a decision request and refused by decide. Only a person can decide them.

Both orders

Vision judges see anonymous, contrast-stretched hotspot strips in both orders. An answer that changes with the order becomes needs_human. Results report answer flip rates and first-slot preference rates.

Canaries

Generated gold questions (identical images, an obvious shadow change, pure noise, a tone shift) are mixed into a judge run. A judge that fails one is flagged and loses weight. A canary pass is an easy-case sanity check, not evidence that hard answers are reliable.

Calibration against people

saccade judge calibrate compares judge answers with human labels: accuracy, agreement, ECE, a reliability table, position bias and Krippendorff's alpha between humans. A threshold is suggested only with at least 10 labelled predictions (--min-support).

Reproducible evidence

This page is generated from real runs. scripts/run-showcases.sh regenerates the datasets and fails on any byte of difference from EXPECTED.txt; it never accepts new output on its own.

Limits. FLIP measures how visible a difference is, not whether it is a bug: a large change can be intended and an invisible one can be wrong. HDR-FLIP uses the reference float algorithm through flip-rs; an all-black baseline needs explicit exposures. Nondeterministic captures need a measured threshold, masks or fixed seeds. All limits.

saccade grew out of the visual-test crate of the Moss engine. The FLIP algorithm is by NVIDIA (Andersson et al., “FLIP: A Difference Evaluator for Alternating Images”, HPG 2020).
