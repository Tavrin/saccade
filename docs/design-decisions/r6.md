# R6 performance qualification

## Decisions

1. R6 owns the performance v2 input and noise contract. The design names required evidence but does not prescribe its field layout. `saccade-perf.v2` has `measurement` and `performance_noise` discriminants, both in ms. Measurement context records source hashes, timer and quantum, sample window and raw-sample hashes, static hardware/driver identifiers, aggregation, coverage/remainder, capture/configuration hashes, producer and versioned qualification checks. Unavailable terms have optional conservative upper bounds. Missing context remains unknown. The original v1 measurement shape and validator remain readable; no v1 qualification is inferred.
2. Qualification is validated producer evidence, not authentication of a producer or independent reconstruction of raw GPU samples. The required checks are `window_complete`, `clock_qualified` and `warmup_complete`; all must be true. Failed checks reject even when both captures have matching false values. Missing checks or required provenance remain unknown. Pair qualification requires matching static hardware, timer, configuration hash, aggregation and qualification-rule identity. The configuration hash identifies the fixed measurement conditions; R7 must encode validated intervention accounting in its producer contract before supporting different configuration identities. Free text does not override mismatches or resolve missing bounds.
3. Only `joint_partition` aggregation supplies a computed additive frame remainder. Independent distributions retain their measured frame and terms and need an explicit remainder bound. Nested scopes never enter frame totals. Scope bounds are accumulated by hierarchy using the maximum of a parent bound and its children's aggregate; disjoint roots are summed, and before/after aggregates are compared using their maximum. Each side adds its conservative frame remainder. An unexplained aggregate equal to the materiality floor is material. Missing timer or term/remainder bounds block `NO-EFFECT`.
4. A known repeat range is separate from repeat qualification. New calibration binds timer, hardware, configuration, aggregation and qualification-rule identity and requires distinct measured windows. Historical performance-noise TOML and legacy nested `perf_noise` records retain their dedicated reader, numerical ranges and unknown qualification. Explicit image-noise JSON cannot become performance noise, including JSON with a supplementary historical performance field. Explicit performance-noise documents cannot become image configuration. Errors name `wrong_noise_kind`, the expected kind and the generating command.
5. The existing image-noise command remains the default and gains compatible kind/unit fields. `noise --kind performance` is the minimum dispatch addition required to make R6's typed output usable; command consolidation stays with R5. Supplementary performance fields in the existing image report/TOML are retained for current readers. The typed performance writer hashes exactly the bytes used for calibration and records paths relative to its output by default.
6. Performance deltas remain inspectable independently of qualification. The frame finding stays unknown until measurement and repeats qualify. A qualified pass change can produce `PERF-ONLY` with the frame within measured noise; the affected term IDs remain in the result. `NO-EFFECT` also requires complete known thresholds and no material unresolved timing. Invalid capture evidence or malformed sidecars cannot produce either strong optimization label.
7. Existing analytical/report writers retain their current containers while adding explicit findings and qualification. Canonical case types and command/report writers consume the qualified input contract and conservative analytical facts. Moss identity JSON fields, report markers, serve routes and flags are retained.
