# R8 decisions

Binding brief: SPEC-r8.md and DESIGN-1.0.md, especially sections 2, 5, 7, 12 and review disposition 10.

- A workbench accepting disposition applies the selected case to an approved snapshot under the configured decisions directory. Its approval receipt names that operation in the attestation audit. The capture archive stays read-only as required by section 2. CLI baseline application remains R1's existing operation and remains unattested; no model or transport can upgrade that channel.
- Scoped tokens are issued only through the local human workbench, after the existing Host, Origin and process CSRF gate. They bind the exact live case, complete case scope, index and presentation assets, expire after ten minutes, and are consumed on the first attestation attempt, including rejected attempts. They appear only in the transient browser session response/body. Artifacts, URLs and audit files contain no scoped tokens. Human identity against unrestricted shell access remains outside this boundary.
- Portable reports bind copied native originals, including HDR originals, rather than tone-mapped display pixels. Sidecars and structured intent are copied into assets; decisions and receipts retain exact hashes. Claims, validity, change and the next action open the page; configuration, criteria, scope, model proposals, human dispositions and proof limits remain available in the same bundle.
- A blind view's default private key is a sibling `<view>-blind-key.json`. An explicit key destination inside the anonymous directory is refused. Anonymous entries use neutral IDs and display PNGs re-encoded without source metadata; original names, source hashes, directory order and labels live only in the private key. Historical keys remain readable. Unblinding restores names and hashes and records mapping exposure when present. Offline exports preserve declared reviewer exposure without granting approval authority.
- Human label export requires explicit question-level human records. Baseline acceptance cannot stand in for a question answer. The existing R9 eligibility, exposure, disagreement and vision-rubric checks decide which records export. Collections without explicit records export an empty labels.v2 document.
- Strictly required adjacent changes: `local_cmd.rs` rebases measured-case inputs, sidecars and intent into the report, refreshes its rendering after intent persistence, and exports explicit question labels; `main.rs` reports the new private key destination; serve state/routes and view-session key storage wire the workbench without changing Moss routes or archive write behavior. `decision.rs` initializes the added optional exposure fields in offline proposal documents. Schema updates are additive to blind keys and historical decisions. Provider adapters, evidence encoders and review profiles are untouched.

Feature gates: default official CLI, core with no default features, core workbench without AI, core schema, CLI with all supported features. All execution is offline; Cargo uses the lane target specified in the brief, except the required external verifier's own self-cleaning target.

The CLI continues to require `view --blind --key-out FILE`; the outside sibling default protects direct library callers. Open the human workbench at `/review?case=RELATIVE/evidence.json` on the loopback server, where RELATIVE follows the same served-root naming rules as browsing. The session reviews the complete preselected case scope. To review a narrower selection, prepare a case/report with that selection first. Accepting review copies the selected native inputs into `reviews/<id>/approved/`; rejecting, needs-work and tie dispositions record attestation without an approval receipt.

Replacing a marked report regenerates its case and clears prior decisions when exact report content changes. Re-rendering unchanged measurements retains canonical workflow records. HTML insertion partitions the template before inserting either summary or JSON, so user text containing placeholder spellings remains text.

Blind exports require a new or empty destination. Reusing a populated named view could retain filenames, originals or decisions that expose the mapping; refusal preserves those existing files and prevents that leak.

The browser review also covers a case at the served root: image URLs remain relative without a leading slash, and opening a fresh scoped session re-enables disposition recording after a prior attestation.
