# R5 local commands and MCP

## Decisions

1. CLI `identity --json` retains `saccade-result.v1` for existing consumers,
   including rendering engines. Compare and MCP results use v2. The shared bounded
   envelope retains mode, verdict, totals, failing errors and report paths;
   historical readers remain. Capture validity, measurement and review authority
   are separate. Changing the identity discriminator requires consumer migration.
2. Compare, identity, noise and serve retain their command names, report markers
   and serving contracts. Advanced workflows use the documented command groups.
3. Serve and MCP share the normalized RootPolicy registry. Startup roots are read-only; targets authorize storage only through root aliases. MCP outputs require a separate explicit out-root. Serve retains its existing default local cache/decision locations and bounded storage probes; explicit out-root feeds those generated locations. Project symlink-target settings cannot grant transport permission.
4. Image noise is explicit `image`/`FLIP`. Performance noise uses the existing dedicated TOML reader/writer representation, with `performance`/`ms` in its result. Performance v2 qualification and wrong-noise-kind validation remain independent of transport.
5. Bounded summaries preserve outcome, counts, validity and actions; full details remain in hashed artifacts. Cursor identity binds artifact bytes, selection and requested page size. Measurement continuations retain deterministic worst-first failing order and resume through inspect at page limit 10. Generated next-action arguments carry the actual local-tool discriminator and are exercised directly by contract tests. Stale action preconditions and changed referenced content fail closed. Grouped capture-invalidity reasons retain the total and the exact report reference.
