# R4 canonical evidence contracts

Binding brief: SPEC-r4.md and DESIGN-1.0.md sections 2–7, 11, 12 and 14.

## Decisions

1. The brief's non-goal lists “R4's canonical evidence types,” which contradicts its goal and Done-when. The explicit R4 goal wins: implement those types. Other lanes' command migration, approval enforcement, performance qualification, evaluation and prechecks remain with their named owners.
2. Cases identify evidence and intent. Workflow records do not change case IDs. Measured/declared facts participate in case identity; model observations and inferences participate in request identity. Requests also bind question wording/answers, encoder, policy, transforms, actual extractor/model/rubric and configured/actual fallback identities. Calibration compatibility identities bind the question, encoder, presentation, observation context and policy; fitted parameters and training splits remain evaluation inputs.
3. A report reference has an exact byte hash and a semantic report hash. Case identity uses the semantic hash, which omits only `generated_at_unix`, `baseline_dir`, `capture_dir` and entry `paths`. Exact report/displayed-content hashes remain available for verification and human review binding. Report-linked facts use the report semantic digest as their source identity; model observations use the actual response content hash. Report byte and semantic hashes are computed from the same read. Hashes of input/sidecar bytes are exact; changing those bytes changes identity. Arbitrary text and configuration keys are never stripped as presumed provenance.
4. Canonical JSON sorts object keys recursively, preserves array order and uses serde_json's round-trip number representation. Integer and float spellings stay distinct. Timestamps and relocatable path spellings in explicit provenance fields are omitted from semantic projections. Duplicate JSON keys and malformed digests fail closed; numeric facts and probabilities must be finite. No RFC 8785 equivalence claim is made.
5. Historical readers preserve original JSON, missing/null fields, attribution and promotion flags. Model-promoted finals remain model-promoted historical records. Human source labels remain unattested; ambiguous origins remain unknown. No reader manufactures a canonical human decision, receipt, current file hash, noise value, semantic label or provider abstention. Old schema IDs/validators remain available, including pre-rename flipdiff IDs. Their validator discriminator and schema ID retain the original name; historical artifacts are not rewritten. Opaque records are archived with their limits, not coerced into validated measurements; existing typed shapes are checked where available.
6. Canonical evidence, result v2 and labels v2 contracts are always readable without optional computation features. New types are shared building blocks for CLI/MCP/providers, not a replacement writer on the current commands. R5 migrates transport writers; R6 owns performance v2, R9 owns the question catalog, and evaluation/precheck producers own their respective experimental contracts. Existing Moss result v1, report markers, routes and flags remain in use.
7. Receipt validation checks channel and exact bindings; it does not authenticate a user/session. CLI receipts have null attestation. A workbench issuer must verify a scoped live token before producing the attestation; R8 owns that operation. Historical records cannot satisfy it. Review bindings include exact displayed-content bytes and reviewer exposure, and ties never authorize an accepting receipt.
