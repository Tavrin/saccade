# R2: strict identity and capture validity

## Decisions

- Identity means equal native decoded samples, dimensions, channel interpretation,
  and sample representation. File-byte equality is a separate finding. FLIP
  metrics describe differences; they do not decide identity. Non-finite samples
  can be equal while capture validity is invalid. Both input sides and alpha
  samples are checked. No tolerance, buffer threshold, mask, or region acceptance
  can relax identity. Explicit entry selection and exclusions are recorded as
  the proof scope; selected CLI scopes are also printed.
- The design does not specify the capture-contract TOML syntax. Use
  `[capture] required_keys = [...]` with nonempty exact sidecar keys. This selects
  a proof profile, requires both sidecars and non-null/nonempty values, and
  enforces undeclared differences. Projects supply their capture-specific mapping,
  including the existing flat `cost-card.json` and per-image overrides.
  `valid` means the supplied capture requirements pass; it does not establish
  producer truth, GPU timing qualification, or renderer correctness. R7 owns
  performance qualification rules and the producer.
- Ordinary image comparison does not require metadata. Absent/empty context is
  `unknown`; matching supplied metadata is `valid` relative to those fields.
  Required absent metadata is `invalid`, even if both sides are absent or a
  wildcard declaration is supplied. Pixel equality is retained in every case.
- Proof profiles use an explicit list of measurement/provenance ignore fields.
  Custom proof ignores must name exact fields. Legacy broad ignores remain for
  ordinary image comparison. `qualification.*` is never ignored. Every ignored
  difference remains in `meta_ignored_diff`. Automatic diagnostic timing globs
  do not widen proof-profile ignores.
- The design does not specify structured-declaration syntax. Use `[[changes]]`
  with `key`, nonempty `reason`, optional `before` and `after` scalar values.
  Expected values are checked against effective sidecars. Existing repeatable
  `--declare` globs stay supported. Common declared keys with equal values are
  reported in `meta_declared_unchanged`; a declaration does not establish that
  the intervention happened. CLI file plumbing belongs to R5.
- New images fail by default. Explicit `fail_on_new = false` is onboarding for
  ordinary comparison only. Identity requires complete pairing. Empty scopes
  fail, including legacy `allow_empty = true` / `--allow-empty`; those surfaces
  remain parsed pending R5's interface migration. Missing evidence never becomes
  equality. Preserve default console headlines until R0 integration is confirmed.
