# R15 release decisions

- Keep the advertised four native targets. Build from a clean checkout at the tag commit with the existing `0.1.0` version. Require `doctor --json` to report the full commit, `git_dirty: false`, and a version equal to the tag without `v`.
- A dispatch run accepts a version label and produces the same archives and qualification artifacts. It cannot create a release. A pull request changing the release machinery also performs a `v0.1.0` dry run at the PR head commit; this is needed while the new `workflow_dispatch` trigger is absent from the default branch. A tag push creates a **draft** only after all four qualification jobs pass; a human publishes it.
- `scripts/generate-third-party-notices.py` uses Cargo's locked metadata because it directly inventories all resolved external crates across optional, build, development and platform dependencies without a separate CLI release. It embeds upstream license and notice files where published and records the SPDX expression/source when a crate has no separate license file. The root MIT and Apache texts are shipped beside it. This overincludes development dependencies deliberately; it cannot omit a target-specific dependency.
- A single `SHA256SUMS` is created from the four completed archives. Qualification downloads that exact artifact, verifies the whole manifest, checks the source commit and version, runs all showcase commands against `EXPECTED.txt`, and validates emitted JSON against shipped schemas. A result JSON carries the archive SHA-256 and commit.
- Qualification pins Python 3.12, Pillow 10.2.0, NumPy 2.2.6 and jsonschema 4.10.3. The nine showcase transcripts and 40 schema-bearing outputs were reproduced with that set locally; wheels were checked for Linux ARM, macOS ARM and Windows x64.
- `cargo package --list` is allowlisted to crate source, tests, examples and intended demo assets. The generated `report/.saccade-run` was excluded from the CLI package. No evaluation or private images are allowed.
- Existing archived `saccade-report.v1`, `saccade-decisions.v1`, `saccade-perf.v1`, and `saccade-evidence.v1` receipt fixtures cover the versions presently in the repository history; no Git release tags exist in this checkout. The focused reader test now names report and receipt compatibility explicitly. Future released schema versions require committed fixtures before release.
- Full SHA action pins apply to every workflow and the composite action. `dtolnay/rust-toolchain` uses a master-history SHA with `toolchain: stable`, since its `stable` ref is mutable.

Residuals: GitHub runner qualification, fork-PR and trusted update demonstrations, Moss consumer integration, browser sizes/themes/offline relocation, and any separately authorized live pilot still require external evidence. macOS notarisation is not provided. The notice generator trusts crate-published license metadata and files; legal review remains human.
