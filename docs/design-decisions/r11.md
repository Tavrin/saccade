# R11 decisions

Binding sources: `SPEC-r11.md` and `DESIGN-1.0.md` sections 2–7, 9, 11–12 and the revised security rows in section 14. No provider or network calls are used for implementation acceptance.

- The ledger uses a separate stable OS lock file and atomic, synced JSON replacement. `fs2` keeps this compatible with Rust 1.88 and Linux/macOS/Windows. A reservation is consumed before dispatch and is never refunded; a crash cannot establish non-dispatch. Run, optional project and optional user-parent scopes are checked in one transaction. Production and evaluation have separate files, counters and failure state.
- User configuration is `~/.config/saccade/user.toml`, or the file explicitly selected by the human with `--user-config`. Root records contain `id`, absolute `path`, and `egress = 'deny'|'allow'`; missing settings deny export. Built-in endpoints and key files remain fixed. Custom provider IDs require HTTPS and their own key file/variable. Authenticated redirects are refused entirely.
- Source provenance retains lexical alias routes and canonical storage paths. Explicit external symlink storage remains usable through an allowed registered root when both alias and target have user permission; it does not become a browsing root. Denial wins for either location and follows relocated artifacts.
- `saccade-review.toml` can reduce budgets/providers and select model IDs and one of the triage/lookdev/ci profiles. Strict deserialization rejects endpoint, credential and authority fields. An explicit project budget creates a separate persistent project scope keyed by its canonical config path. Editing its budget/profile cannot reset consumed attempts or raise the recorded ceiling.
- CLI `review --run` authorizes only that invocation. MCP requires both startup `--allow-provider-calls` and a positive `--budget-calls`; tools can only reduce that cap. The default CLI cap is 24, with at most 6 Jev attempts, 18 Gemini attempts and three visual entries. Every retry/fallback uses the same boundary. Both blind orders keep the first actual model and the same configured fallback identity.
- Canonical Jev currently supports one request per batch. Evaluation planning uses that actual adapter limit rather than the design's illustrative eight-item batch arithmetic. Manifests are strict JSON/TOML with immutable local references, explicit mode, budgets, retry/window/cache policy, split/label/exposure identities and unknown prices. Pinned evaluation never substitutes a model. Jobs share planning/resumption; waits are persisted, and model/question groups are round-robin scheduled. Gemini visual exchanges use R10 presentations and the same transport; R12 owns the real direct/enriched/Gemini comparative corpus.
- Conditional accuracy uses labelled committed answers. Failures and missing responses are separate from valid abstention, availability and answer coverage. Confidence intervals resample independent cases, keeping repeated orders together. Calibration fits only the calibration split and binds the full R9 identity. Synthetic and unlabelled cells provide no quality support. Transport completion never qualifies routing by itself.
- Review output uses canonical case/request/proposal documents, with a separate local payload plan and response artifacts. These are proposals with unresolved human review. The historical benchmark remains an offline smoke/replay interface; it cannot qualify or alter the operational Gemini catalog.

Strictly required adjacent changes: feature-gated ledger dependencies/module exports; CLI review/evaluation and MCP startup wiring; fixed catalog request preparation; original source-root provenance in the measurement-to-case producer and its shared portable path helper; existing tool-inventory tests updated for the sixth compiled tool; a historical review fixture discards its canonical case after deliberately editing the report; and an existing MCP-only noise helper gated with MCP after the CLI build without defaults exposed it as unused. No report/view assets, renderer, decisions or approval receipts are edited. Explicit new intent creates a new case and removes copied workflow state from that new case; the source artifact is untouched.

Verification matrix: default workspace; all features; core without defaults, core with ai, core with evaluation, core with workbench; CLI without defaults, CLI with mcp, and CLI with ai,mcp. Focused fixtures cover real concurrent processes, crash-held locks, retry/fallback/deadline/resume behavior, conditional scoring, every security row and all six tools.
