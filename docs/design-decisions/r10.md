# R10 decisions

R10 implements DESIGN-1.0 §§5, 8.2–8.5, 9's same-model rule, 11 and 14.
The visual encoder always supplies two anonymous full frames, with each image's
long edge capped at 1536 pixels, and at most three native-resolution ROI pairs.
Raw display crops are retained beside separately labeled enhanced crops. A shared
gain is applied to both sides of an enhancement. The existing strip helper resizes
crops, so it cannot implement the native-resolution contract; R10 has a separate
native crop encoder and preserves the historical strip reader's behavior.

The design does not specify a wire format for visual extraction. R10 uses a strict
body that echoes the presentation digest and contains typed observations or a
separate closed blind preference. Region IDs are anonymous `r1` through `r3`.
Directional descriptions retain the supplied wording and record explicit stable
`from_input` and `to_input` identities after private remapping. R10 does not invent
antonyms for free-text visual descriptions. Full-frame observations use
`full_frame`. Directional observations must cite both anonymous slots in their
region. Empty extraction remains an explicit shortfall and cannot form an enriched
request; it is never synthesized into an abstention or a visual fact.

Local source loading uses the canonical path helper, hashes the original content,
checks for source changes during decoding, and records the display transform.
LDR uses sRGB and an explicit compositing background. HDR reuses the existing
zero-exposure display conversion, with `hdr-display/1`, its canonical tone mapper,
and exposure recorded. Unsupported HDR conversions fail instead of being guessed.
Input hashes, attachment hashes, native rectangles, transforms, anonymous ordering,
rubric and source provenance bind the private presentation. The provider packet
contains no filenames, stable source labels, routing proposal, declared intent,
performance gains or project semantics. Image text and supplied content are data.

Actual Gemini identity comes from the adapter-selected model and the provider
envelope's resolved `modelVersion`. Missing revision, blocked/truncated responses,
unknown citations, mixed actual models/revisions, changed presentations and
contradictory orders cannot resolve a blind pair. Both-order preference remaps to
stable source inputs; two ties remain a tie, and a tie or abstention mixed with a
preference escalates. Confidence is not combined or treated as independent proof.
The configured fallback policy and actual completed outcomes have separate digests.
Retries, fallback execution, model qualification and shared budgets remain R11/R12.

The existing Jev choice protocol supplies a choice and optional distribution,
without per-fact citations or rationale. R10 retains all available selected inputs
as conservative dependencies and explicitly labels that adapter decision. It does
not invent model-selected citations or explanations. Distribution validation uses
the canonical proposal validator; missing probabilities remain null. Exact wire
payload/response hashes and separately supplied actual model identity are retained.
The Jev adapter implements R9's `DecisionProvider` through a caller-owned exchange
interface. Gemini payload and envelope adapters are pure preparation/validation
functions. There is no new HTTP dispatcher, key access, retry loop or authorization
path. R11 connects these adapters to its authorized shared-budget transport.

Enriched requests are created only after extraction identity is complete. Canonical
facts retain `model_observation` attribution and original response content hashes.
Request/calibrator identity includes actual model/revision, rubric, transforms,
configured fallback policy and actual outcome. Proposal validation propagates the
dependency from cited observations and inferred facts. Direct and enriched request
identities remain separate. Human decisions and baseline approval are unchanged.

The initial `triage`, `lookdev` and `ci` profiles plan Jev routing, direct visual
look-development, and advisory text-first CI respectively. Plans grant no egress
or execution authority. The older named profiles remain readable for existing
consumers. The historical review cascade receives the same-model/revision and
tie checks and no longer sends declared intent to blind preference. R11 owns
redirecting the supported command workflow to canonical questions and adapters.
No change outside the evidence encoder, provider adapters, review coordinator,
profiles, focused conformance tests and this record is required.

Feature gates cover core-only, AI-only, evaluation, and AI plus schema, in addition
to the default workspace and the prechecks-enabled binary for showcases. Tests use
recorded responses and generated local pixels only. They establish conformance,
not provider quality, live availability or native macOS/Windows execution.

The prescribed verification script chooses its own `verify-r10` target and invokes
the local Moss ablation tests. This is the explicit spec-required exception to the
lane's Cargo target. All Cargo runs use offline mode, an empty `RUSTC_WRAPPER`, and
two build jobs. The lane target is removed after validation; the verification script
removes its own target on success. No Git mutation or live provider call is used.
