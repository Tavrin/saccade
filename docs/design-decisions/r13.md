# R13 documentation, demos and generation

## Decisions

- Maintained task docs use the implemented R5 commands. Dated live-review and
  recovery notes remain historical evidence, not instructions. Historical schemas
  stay in the generated reader index.
- Copyable inspection and review commands name the measurement JSON explicitly;
  those operations require a document path rather than the output directory.
- Binary installation describes release archives and checksum verification without
  claiming that an unpublished release or Action tag exists. Source installation
  and local smoke checks use the current checkout and no network.
- The rights-cleared rendering example is the repository-owned CPU analytic sphere
  renderer. Its existing MIT OR Apache-2.0 license grants redistribution of code
  and generated assets. Provenance records license permission, source hashes and
  exact asset hashes. This is a real local rendering of a procedural scene; it is
  not a Moss GPU capture, third-party asset clearance or benchmark. No private
  capture is copied or published.
- Review demo responses and resolution are labeled illustrative offline fixtures.
  Canonical records bind measured inputs, declared criteria, attributed fixture
  providers, disagreement and scoped resolution. They have no live-provider claim,
  attestation or baseline application. A real human decision cannot be fabricated
  by an offline implementation lane. Minimal builds retain the images and fixture
  explanation; canonical request/proposal construction requires AI computation.
- Pack budget uses the documented estimate of UTF-8 bytes divided by four, bounded
  at 4,800 bytes. Both entry packs are generated from the single shared guide.
- Generators read/write UTF-8 and emit LF explicitly; checks also run under a
  non-UTF-8 default locale. This avoids Windows locale-dependent decoding of
  report JavaScript and generated schema descriptions.
- Schema links and showcase counts come from shipped files; CLI reference comes
  from compiled capabilities and recursive help. Generation has a check mode.
- Public gallery copies redact local paths. This changes measured report bytes,
  so the generator refreshes exact report references in unreviewed cases and facts.
  Semantic case/measurement identities remain unchanged. Copies with bound workflow
  records refuse redaction instead of changing reviewed content automatically.
- Full showcase validation requires default CLI features plus `prechecks` and
  fails before generation with the exact build hint if unavailable. The default
  Pages build shows all nine cases, labels the precheck unvalidated and uses static
  previews; a prechecks build executes that case as well. This retains the Pages
  workflow's default build without changing the parallel workflow lane.
- Feature gates for this lane: default CLI, default plus prechecks, all features,
  minimal CLI and minimal core. No provider is called by documentation generation,
  demo or smoke checks. Existing local transport fixtures remain part of tests.

## Strictly required changes outside documentation and assets

- `f1.rs` and the local demo helper: ship and render the identity/UI/review examples
  while preserving the default demo's real comparison exit status.
- `local_cmd.rs`: recognize a marked demo root so the design's copyable
  `saccade view saccade-demo` succeeds.
- The identity command's help text describes native equality and selected scope.
- Report HTML metadata and summary: identity shows native proof and supplied scope
  instead of threshold, metric and PPD as acceptance settings. Regression headers
  retain those settings. Identity JSON, console wording, markers and serve contracts
  remain unchanged.
- Tests exercise copyable commands, compact generated packs, indexes, asset labels,
  license/hash provenance, current instructions, demo disagreement and missing
  precheck guidance. The report test checks the actual rendered header and scope.
