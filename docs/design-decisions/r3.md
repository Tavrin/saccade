# R3: cargo feature boundaries

## Decisions

- The core defaults to `parallel` only. The CLI explicitly forwards library
  features and defaults to `parallel`, `graphics`, `ai`, `workbench`, `mcp`,
  and `evaluation`. `evaluation` enables `ai`; `workbench` and `prechecks` do
  not. `prechecks` and `schema` are opt-in.
- `parallel` selects the FLIP backend, as specified. Rayon remains available
  for the existing image diagnostics and offline rendering code.
- Existing report, graphics-result, label, inbox, and human-vote types and
  their readers remain available without their computational producers.
  Producer entry points that return `Result` report `feature_unavailable`
  with the required feature before writing outputs. Graphics-only low-level
  calculations are compiled only with `graphics`.
- An ordinary image comparison, image-noise measurement, or offline view
  does not implicitly ingest performance sidecars when `graphics` is absent.
  Explicit performance options and buffer configuration require `graphics`.
  This preserves the always-available image workflow while making requested
  unavailable computation an error.
- `inspect capabilities` reports the compiled inspection surface.
  Capabilities derive operations from the compiled Clap command tree and
  report actual compiled features. MCP filters optional tools and performance
  arguments and rejects requests for missing computations with the same code.
- The historical standalone watch workflow has no watcher feature. Their module, command, MCP option/tool, dependency, and obsolete
  tests are removed from compiled targets. The unrelated provider and command
  changes have separate feature boundaries.
- Showcase validation uses a binary with `prechecks` enabled because the
  maintained photosensitivity showcase exercises that experimental feature.
  The official default binary keeps it disabled.
