# R3: cargo feature boundaries

Binding brief: `/home/etienne/dev/specs/saccade/lanes/SPEC-r3.md` and
`DESIGN-1.0.md` sections 3 and 12, with section 14's revisions.

## Decisions

- The core defaults to `parallel` only. The CLI explicitly forwards library
  features and defaults to `parallel`, `graphics`, `ai`, `workbench`, `mcp`,
  and `evaluation`. `evaluation` enables `ai`; `workbench` and `prechecks` do
  not. `prechecks` and `schema` are opt-in.
- `parallel` selects the FLIP backend, as specified. Rayon remains available
  for the existing image diagnostics and offline rendering code.
- Existing report, graphics-result, label, inbox, and human-vote types and
  their readers remain available without their computational producers.
  Producer entry points that return `Result` report `feature_unavailable`
  with the required feature before writing outputs. Graphics-only low-level
  calculations are compiled only with `graphics`.
- An ordinary image comparison, image-noise measurement, or offline view
  does not implicitly ingest performance sidecars when `graphics` is absent.
  Explicit performance options and buffer configuration require `graphics`.
  This preserves the always-available image workflow while making requested
  unavailable computation an error.
- R3 adds only `inspect capabilities` from the future inspection surface.
  Existing command names and result schemas remain in place for R5/R4.
  Capabilities derive operations from the compiled Clap command tree and
  report actual compiled features. MCP filters optional tools and performance
  arguments and rejects requests for missing computations with the same code.
- Section 11 retires standalone watch and notify without defining a watcher
  feature. Their module, command, MCP option/tool, dependency, and obsolete
  tests are removed from compiled targets. The unrelated provider and command
  redesigns remain with their owning lanes.
- Showcase validation uses a binary with `prechecks` enabled because the
  maintained photosensitivity showcase exercises that experimental feature.
  The official default binary keeps it disabled.

## Required changes outside the named files

- The workspace manifest disables inherited dependency defaults so the crate
  manifests can actually select the sequential FLIP/core-only build. Cargo.lock
  removes dependencies that were used only by the retired watcher.
- `local.rs` holds the existing directory defaults and token generator. Inbox,
  provider, vote, and CLI consumers no longer require the HTTP server module
  merely to choose local storage or generate an opaque identifier.
- Graphics modules retain their evidence types but gate producer functions.
  Configuration, comparison, image-noise, diagnostics, view, and run overview
  callers avoid optional computations in reduced builds. Rendering helpers
  needed only by the server are gated.
- Labels share their existing hash implementation with review; offline label
  validation uses the always-available decision question catalog. Replay,
  collection, calibration, benchmarks, and conformance use `evaluation`.
  A11y image uploads require `ai` independently of deterministic `prechecks`.
- Existing integration suites and the label-building example declare their
  required features. The self dev-dependency that implicitly enabled core
  defaults/schema is removed; the schema suite explicitly requires `schema`.
  The two focused feature-boundary suites exercise dependency isolation,
  offline evidence reads, missing computations, CLI capabilities, and MCP
  advertisements. Retired watch tests are removed; the serve-specific exit
  test is gated by `workbench`.
