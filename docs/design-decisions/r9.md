# R9 decisions

R9 follows DESIGN-1.0 §§3, 5, 8 and 14. It supplies exactly five versioned
question schemas, structured evidence selection, a small decision-provider
interface, proposal validation, calibrator identities and human label records.

The catalog lives in `questions.rs` and remains readable in core-only builds.
Each definition produces an exact JSON question schema and declares evidence,
answers, abstention, deterministic constraints and scoring. New dispatch and
proposal preparation validate the catalog. Historical R4 artifact readers retain
their original closed question instances; they are not a supported dispatch path.
Removed, deferred and unversioned question IDs fail catalog lookup.

Evidence features reference R4 facts with their units, source, availability and
immutable artifacts. Context and report projections are added before case identity
is finalized. Changing a case with attached workflow records fails transactionally
and requires rebuilding those records. Selected aggregates retain their members
and additivity semantics. Feature selection records omissions and full report
hashes. Requests are bounded to 64 KiB. Provenance retains the union of case and
input source roots for later egress checks. Diagnostics retain their measured
numbers; the new grid carries unrounded means, maxima, precision and non-finite counts.
Unsupported features remain missing, including qualification that the producer
did not supply. Legacy color, OCR and strip helpers remain for existing consumers.
Full-frame vision extraction and adapters belong to R10.

The design allows missingness to be evidence without listing every such case.
R9 permits explicitly missing noise, intent, semantic features, repeats,
attribution, counters and capture context when the question can request more
evidence or human review. It prohibits the corresponding confident conclusions.
Performance deterministic findings and qualification must be present; a false
qualification supports evidence collection, never a qualified result. Missing
or invalid captures cannot continue review. Intent consistency requires structured
intent and actual attributed observations. Models never compute identity,
qualification, thresholds, capture retries, queue priority or approval.

`DecisionProvider` uses canonical requests and answers. Adapter audit identities
are assigned separately from strict model JSON. Probabilities remain null when
absent. Provider failure remains unavailable, rather than becoming abstention.
Existing transport orchestration is not redirected into this interface in R9:
R10 owns vision adapters and R11 owns authorization, dispatch, shared budgets
and the final MCP surface. R9 tests recorded responses only.

Human vision labels retain the exact structured packet hash, initial assessment,
anonymous pixel assessment, concrete necessary fact, minimum scope, separate human
judgment requirement and exposure. Undetermined pixel need remains undetermined.
Pixel-need detection and route agreement are scored separately. Exposed or
unknown-exposure records remain in the history but are excluded from unexposed
ground-truth export. Disagreement, supersession and test-retest records are kept.

R4's `saccade-labels.v2` shape has no fields for the complete human rubric and
history. R9 records those annotations as `saccade-evaluation.v1` with
`kind: human_label_records`, then exports eligible answers using R4's exact
labels.v2 type. This avoids a second incompatible labels.v2 writer or changes
to R4's canonical types. Baseline approval is not inferred as a question label.

Calibrator identity binds project, versioned question, actual decision model,
encoder, label set, split, actual vision model/revision, observation rubric,
presentation transforms, configured fallback chain, actual fallback outcome and
effective policy. Direct and enriched requests cannot reuse each other's
calibrator. Fitting, pooling, corpus support and model qualification remain R12.

The only implementation outside the named R9 files is module registration in
`lib.rs`, required to expose the new catalog and AI-gated provider interface.
No Git state change, external network request or live provider call is part of R9.

The lane's feature gates cover core-only, AI-only, evaluation, and schema plus AI,
in addition to the default workspace and the prechecks binary for showcases.
The mandated external verification script chooses its own `verify-r9` target;
that is an explicit exception to the lane target path and cleans itself on success.
The lane's own Cargo target is removed after all gates finish. Local Linux results
do not establish native macOS/Windows execution or provider/model qualification.

## Validation

Cargo used `CARGO_NET_OFFLINE=true`,
`CARGO_TARGET_DIR=<local-scratch>`,
`RUSTC_WRAPPER=` and `CARGO_BUILD_JOBS=2`. The empty wrapper avoids the local
sccache service, which failed an earlier compilation with an allocation error.
The ignored `.tools/actionlint` executable was copied from the existing local
main checkout; no download was performed.

| Command | Final exit | Evidence |
|---|---:|---|
| `cargo fmt --check` | 0 | Final source formatted |
| `cargo clippy --all-targets -- -D warnings` | 0 | Default workspace |
| `cargo clippy -p saccade-core --all-targets --no-default-features -- -D warnings` | 0 | Core-only |
| Same core Clippy command with `--features ai`, `--features evaluation`, and `--features ai,schema` | 0 each | All lane feature combinations |
| `cargo test` | 0 | 227 passing tests, including 13 R9 tests |
| `cargo test -p saccade-core --no-default-features --test r9_questions` | 0 | Three offline catalog tests |
| Same focused test command with `--features ai` | 0 | All 13 R9 tests |
| `.tools/actionlint` | 0 | Existing CI workflows |
| `cargo build -p saccade --features prechecks` | 0 | Lane binary for all showcases |
| `scripts/run-showcases.sh` | 0 | All nine EXPECTED transcripts reproduced |
| `<coordinator-tools>/verify-lane.sh <lane-worktree>` | 0 | Printed PASS; nine showcases and Moss ablation tests passed |

Showcases used the lane's `debug/saccade` first on PATH and wrote reports inside
the lane target. The verification script built its own release binary. Final
showcase and verification runs were serialized: an earlier overlapping run read
a partially rewritten generated PNG and failed one transcript. The serial run
reproduced it without an implementation change.

The lane target was removed after validation with `cargo clean --target-dir
<local-scratch>` (exit 0); the verification
script removed its own target. Both paths were checked absent. Logs remain in
`/tmp/saccade-r9-*.log`. The next collector action
is to review these file edits and integrate them through the coordinator.
